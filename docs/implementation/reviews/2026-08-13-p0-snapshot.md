## Achados do snapshot anterior — estado de resolução

### P0-R01 — bloqueador: Ajv sem lockfile — **RESOLVIDO**

`p0/package-lock.json` existe; o gate `lockfile` passa. Instalação reprodutível e auditável recuperadas.

### P0-R02 — bloqueador do WP-05: contrato de geração divergente — **RESOLVIDO** (2026-08-14, WP-05-R)

As três relaxações (`strictSchema: false`, `validateSchema: false`, `strictRequired: "log"`) foram removidas do `createAjv()` em `p0/scripts/generate-contract-validators.mjs` — com `strict: true`, os defaults são os exigidos. Validators regenerados com `npm run generate-validators`; `npm test` (152/152), `npm run check-drift`, `npx tsc --noEmit` e `cd review && npm run full` (7/7 PASS) confirmam. Observação: a regeneração estrita expôs duas fixtures inválidas do conjunto paralelo do WP-09A (`price-book` com `"currency": "default"` e `tool-definition` com enum inválido); a LLM paralela corrigiu ambas e hoje as 44 fixtures validam sob strict.

### P1-R03 — fronteira arquitetural do relógio — **RESOLVIDO**

`domain/clock.ts` contém apenas fakes puros; `SystemAuditClock`/`SystemMonotonicClock` estão em [`p0/src/adapters/system-clock.ts`](../../../p0/src/adapters/system-clock.ts). O gate `source-policy` (que detecta relógio global em `domain/`) passa.

### P1-R04 — classificação incorreta do budget — **RESOLVIDO**

`budget.ts` foi registrado como WP-06 concluído; WP-15C permanece pendente até os pré-requisitos da Onda B estarem integrados. Seus arquivos obrigatórios continuam inexistentes.

### P2-R05 — IDs não são opacos no sistema estrutural do TypeScript — **RESOLVIDO** (2026-08-14, WP-02B-R)

`ids.ts` declara 29 `declare const xxxBrand: unique symbol;` **não exportados** e cada interface usa `readonly [xxxBrand]: "X"` no lugar do `__brand` estrutural. Nenhum código externo consegue nomear o symbol, logo o tipo não é fabricável nem intercambiável; os `parse*`/`create*` mantêm as mesmas assinaturas e retornam `{ value } as X` (cast único dentro do módulo). Prova compile-time em [`p0/test/domain/ids-opacity.test.ts`](../../../p0/test/domain/ids-opacity.test.ts) com `@ts-expect-error` sobre erros reais; `npx tsc --noEmit` passa.

### P2-R06 — testes de ID não leem os vetores como fonte de verdade — **RESOLVIDO** (2026-08-14, WP-02B-R)

[`p0/test/domain/ids.test.ts`](../../../p0/test/domain/ids.test.ts) carrega `id-vectors.json` (29 válidos / 10 inválidos) via `readFileSync` + `JSON.parse` com caminho resolvido por `import.meta.url` e despacha por tipo: todo vetor válido passa no parse e retorna o mesmo `value`; todo inválido lança `InvalidIdError` com code `invalid.id`. Casos além dos vetores (não-string, troca de prefixo entre tipos válidos) foram mantidos.

### P2-R07 — documentação do esqueleto está desatualizada — **RESOLVIDO**

[`p0/README.md`](../../../p0/README.md) declara a dependência Ajv 8.20.0 (draft 2020-12), os comandos de geração/typecheck e a ausência de import da árvore `packages/`. Não há mais a afirmação falsa de zero dependências.
